Runner does some work once, when it packages the application, instead of at every start. Each step is on by default
and can be turned off. The build log says what each step did, and why when it did nothing; in Gradle, run with
`--info` to see these lines.

[cols="3,2,4,3",options="header"]
|===
|Step |Default |What you may notice |Option

|<<precompiledLogback,Precompiled Logback configuration>>
|On
|A `logger.config` set outside the archive is not applied.
|`precompileLogback`

|<<desugaredLambdas,Lambdas generated at build time>>
|On, except with `PRESERVE`
|One extra frame per lambda call in stack traces.
|`desugarLambdas`

|<<staticServices,Precomputed service lookups>>
|On, for micronaut-core 5.1.10 up to 5.2
|A service provider added after packaging is not seen.
|`staticServices`
|===

Runner verifies every class it rewrites. When a rewrite fails, it keeps the original class and says so in the build
log. It never rewrites the classes of signed JARs. `inspect` lists what the class rewrites changed
(<<quickStartCheck,Checking the Archive>>); the build log reports every step.

One more class rewrite is off unless you turn it on: dropping the local-variable names of dependency classes
(<<localVariableTables,Opt-in: Dependency Local-Variable Names>>).

To turn steps off, set their options to `false`. To rule Runner's build-time steps out while you track down a
problem, turn off all three:

[source.multi-language-sample,groovy]
----
micronaut {
    runner {
        options.put('precompileLogback', 'false')
        options.put('desugarLambdas', 'false')
        options.put('staticServices', 'false')
    }
}
----

[source.multi-language-sample,kotlin]
----
micronaut {
    runner {
        options.put("precompileLogback", "false")
        options.put("desugarLambdas", "false")
        options.put("staticServices", "false")
    }
}
----

In Maven, in the plugin's `<configuration>`:

[source,xml]
----
<configuration>
    <runnerOptions>
        <precompileLogback>false</precompileLogback>
        <desugarLambdas>false</desugarLambdas>
        <staticServices>false</staticServices>
    </runnerOptions>
</configuration>
----

Maven also takes `-Dmicronaut.runner.<option>=false` on the command line. `PRESERVE` compression turns off only the two class
rewrites (<<compression,Compression Modes>>).

Other differences from a shaded JAR do not come from these steps:

* A library does not find your dependencies' classes if it looks for them through the system class loader, in the
single JAR, or by scanning only the files that `java.class.path` names, in either layout. Micronaut does neither
(<<compatibility,Compatibility and Limitations>>).
* Signed dependencies are not verified in the single JAR, which matters to a signed JCE provider on Oracle JDK or
Oracle GraalVM (<<compatibility,Compatibility and Limitations>>).
* A dependency's own `Class-Path` manifest attribute is ignored (<<compatibility,Compatibility and Limitations>>).
* A deployed Runner JAR must never be modified, signed or re-zipped (<<archiveLifetime,Archive Lifetime>>).
