https://micronaut-projects.github.io/micronaut-aot/latest/guide/[Micronaut AOT] holds build-time optimizations that
every packaging can use, so that a shaded JAR, a container image and a native image benefit from them as well as a
Runner JAR. Its optimizer generates optimized application code when you build. Logback precompilation needs no
optimizer run: the Micronaut Gradle and Maven plugins apply it themselves, and a Runner JAR gets it by default
(<<precompiledLogback,Precompiled Logback Configuration>>).

Runner adds what its archive and its launcher make possible: the index, the class loader and the startup profile, and
the steps it takes while it packages the application (<<whatChanges,What Changes for Your Application>>). It packages
the output of Micronaut AOT's optimizer, and never runs the optimizer itself.

== Gradle

In a project that applies `io.micronaut.aot` next to a Micronaut application plugin, as Micronaut Launch generates it,
the `io.micronaut.runner` plugin adds the task `optimizedMicronautRunnerJar`. It is part of `assemble`:

[source,bash]
----
./gradlew optimizedMicronautRunnerJar
java -jar build/libs/my-app-0.1-all-optimized.jar
----

`-all.jar` never contains Micronaut AOT's output. Both archives take the options of `micronaut { runner { } }`. If
the Shadow plugin is still applied, give `optimizedJitJarAll` another classifier, as
<<quickStartGradle,Quick Start for Gradle>> shows.

== Maven

Maven has no separate optimized archive. In a project built on `micronaut-parent`, set the property
`micronaut.aot.enabled` to `true`: the Micronaut Maven plugin's `aot-analysis` goal then rewrites `target/classes`
before the `package` phase, and the Runner JAR is the optimized application. Without the property, it is the plain
one.

Micronaut AOT reads its settings from the file that the plugin's `configFile` parameter names. When your POM names it
after the packaging, as `+aot-${packaging}.properties+` does in projects that Micronaut Launch generates, `runner`
packaging reads `aot-runner.properties`. Launch generates that file when you select the `runner` feature; when you
switch an existing project, copy your `aot-jar.properties` to that name. Without the file, Micronaut AOT runs with its
defaults and says nothing.

== What the optimized application changes

Depending on the optimizations you enable, the optimized application can behave differently from the plain one, in a
Runner JAR as in Micronaut AOT's own Shadow JAR. The
https://micronaut-projects.github.io/micronaut-aot/latest/guide/[Micronaut AOT guide] describes each optimization.
To go back, deploy `-all.jar`, or turn off the optimization that causes the change.

When the optimizer's `logback.xml.to.java` optimization, `replaceLogbackXml` in Gradle, has already replaced
`logback.xml`, the optimized archive keeps that configuration, and Logback precompilation does nothing there. The
precomputed service lookups and the class rewrites still apply.

== Startup profile and JDK AOT cache

In Gradle, `recordStartupProfile` records from `-all.jar`, and both archives embed the committed profile. The optimized
application loads other classes, so if you deploy `-all-optimized.jar`, record a class-load log of a run of it and
embed that list instead, with the `startupClasses` option (<<configurationOptions,Packaging Options>>):

[source,bash]
----
java -Dmicronaut.runner.preload=false -Xlog:class+load:file=optimized-classes.log -jar build/libs/my-app-0.1-all-optimized.jar
----

To add a JDK AOT cache, train it on `-all-optimized.jar` itself, as
<<jdkAotCacheSingleJar,The Cache on the Single JAR>> describes; a cache trained on `-all.jar` does not fit it.

== Which archive to deploy

Without a JDK AOT cache, `-all-optimized.jar` starts fastest, and even `-all.jar` starts faster than Micronaut AOT's
optimized Shadow JAR. With a JDK AOT cache, the two archives start in about the same time, so `-all.jar`, which keeps
the plain application's behaviour, is the simpler choice.
