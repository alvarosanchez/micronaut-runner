Micronaut Runner's startup claims come from a harness in the repository; this page publishes one CI run of it. How
the harness works is in https://github.com/{githubSlug}/blob/master/benchmarks/README.md[`benchmarks/README.md`].

== What is measured

* *JMH*: class loading and resource lookup against two JDK baselines built from the same inputs: a flat single JAR
(the Shadow and Shade layout) and a multi-JAR `URLClassLoader` (the thin or exploded layout).
* *Packaging*: `micronautRunnerJar` against `shadowJar` in a warm Gradle daemon. Maven Shade is not compared.
* *Startup*: `test-suite/samples/benchmark-large` (Micronaut Netty, 49 dependency JARs), packaged as each row below.

[cols="38,62"]
|===
|Row (* opt-in) |Packaging
|`exploded-cp` |Class files and dependency JARs on an explicit class path
|`thin-jar` |An application JAR with a `Class-Path` manifest
|`shadow` |One JAR flattened by Gradle Shadow
|`shadow-stored` |The same Shadow inputs with `STORED` entries, a compression-matched control
|`shadow-aot` |`shadow` with a trained JDK AOT cache
|`runner-stored` |Runner JAR: dependencies re-packed uncompressed (`STORED`), entered through the entry stub
|`runner-stored-aot` |`runner-stored` with a trained JDK AOT cache: the single-file option
|`runner-stored-reflection`* |`runner-stored` entered by reflection instead of the entry stub
|`runner-stored-preload`*, `-aot`* |With the startup classes recorded from `runner-stored` in the same run
|`runner-stored-positional`*, `-aot`* |`archiveReads=POSITIONAL`: only the index is mapped
|`runner-stored-prefetch`*, `-aot`* |`definitionPrefetch=true`
|`runner-stored-joran`*, `-aot`* |Control: `precompileLogback=false`
|`runner-stored-keepdebug`*, `-aot`* |Control: `stripLocalVariables=false`
|`runner-stored-dynamic-services`*, `-aot`* |Control: `staticServices=false`
|`runner-stored-lambdas`*, `-aot`*, `runner-extracted-lambdas-aot`* |Control: `desugarLambdas=false`; the last extracted
|`runner-preserve` |Runner JAR with the dependencies copied byte for byte (`PRESERVE`)
|`runner-extracted` |`runner-stored` extracted into the plugins' layout, run by the JDK's own loader
|`runner-extracted-aot` |That layout with a trained cache: the AOT layout the plugins generate, the cached headline
|`shadow-maot`, `shadow-maot-aot`* |Micronaut AOT's `optimizedJitJarAll`, flattened by Shadow (`-aot`: with a cache)
|`runner-maot`, `runner-maot-aot`* |Runner JAR of Micronaut AOT's `optimizedJitJar`, as `optimizedMicronautRunnerJar`
|===

* The Runner rows use the plugins' defaults of the day, build-time transforms included; the Shadow rows use the
dependencies unmodified.
* Each sample is a fresh JVM; readiness runs from spawn to the first HTTP 200 on `/hello`.
* Rows run interleaved in a random order within each iteration and are compared as within-iteration pairs.
* The OS page cache is uncontrolled by default; Linux runs can pin CPUs and evict it (`-Pbenchmarks.cpus`,
`-Pbenchmarks.pageCache`).
* Timing runs carry no `-Xlog`; memory and class counts are read after readiness and are not timed.
* A trained cache is its own row, distinct from the JDK's default class sharing.
* Opt-in rows are built only on request and never gate a run.

== Results

From https://github.com/alvarosanchez/micronaut-runner/actions/runs/36818155119[one CI run] on 2026-10-01: commit
`2ef8217` (master `9aef0be` plus the harness's build log), GitHub `ubuntu-24.04` runner (image 20260920.314.1, 4
vCPUs, AMD EPYC 7763), *JDK 25.0.4.1+1-LTS* (Temurin, HotSpot C2), `benchmark-large` on Micronaut 5.1.15 and Netty
4.2.18.Final, 3 warm-up and 20 measured iterations per row. Lines that name another run or JDK say so.

*Build-time steps* of `runner-stored`, and so of `runner-stored-aot`, as the build log shows them
(<<buildTransforms,Build-Time Transformations>>):

* Local-variable stripping and lambda desugaring: on (7102 classes, 2963 call sites); no effect in `runner-preserve`.
* Logback compilation: on; stood down in `runner-maot`, which has "no logback.xml" after Micronaut AOT.
* Static service table: on (486 slots for micronaut-core 5.1.15). Definition prefetch: off. Archive reads: `MAPPED`.
* Preloading: only the `runner-stored-preload` rows. The plugins' convention needs a committed startup profile, which
the sample lacks, and the harness calls the packaging library directly.
* The extracted rows keep the rewritten classes, the Logback configurator and the service table; the entry stub, the
prefetch, preloading and the read mode do not apply to them.

*Libraries.* On Micronaut 5.1.15 and Netty 4.2.18.Final the first request still sets up JFR with nothing recording,
so every row, Runner and Shadow alike, includes that cost; the unreleased fixes for
https://github.com/micronaut-projects/micronaut-core/issues/13386[micronaut-core#13386] and
https://github.com/netty/netty/issues/17612[netty#17612] remove it.

== When Runner beats a shaded JAR, and when it does not

From the tables above, JDK 25.0.4.1+1-LTS unless named:

* *No JDK cache: Runner wins*, `runner-stored` − `shadow` -464.0 ms (-479.9 to -453.1), -33.2%. Compression-matched,
`runner-stored` − `shadow-stored` is -387.8 ms (-404.6 to -375.4) and `runner-preserve` − `shadow` -233.3 ms, against
-80.5 ms for compression alone (`shadow-stored` − `shadow`): most of the lead is Runner's layout and default steps.
* *Inflating classes*: `runner-stored` − `runner-preserve` -220.1 ms (-248.1 to -209.3), which also includes the class
transforms `runner-preserve` does not run. A step's share is only its own line under "What each default buys".
* *Opt-in accelerators*, each measured alone, never added up: preloading -136.1 ms (-148.6 to -127.9), -11.3 ms
(-18.1 to -5.1) with the cache. Positional reads are slower, +26.8 ms (+16.3 to +33.3) and +23.2 ms (+9.6 to +28.2).
The definition prefetch's intervals include zero on these 4 vCPUs.
* *Trained caches*: the cached headline is ahead, `runner-extracted-aot` − `shadow-aot` -27.1 ms (-30.7 to -16.9),
with 8.8 MiB less private memory, but it is a directory of JARs plus a cache file. The single-file
`runner-stored-aot`, already desugared, still loses on JDK 25: +17.4 ms (+12.1 to +22.5). On JDK 27 the layout stays
ahead and the single JAR trails by 76.0 ms; <<cdsAndAot,Class Data Sharing and the AOT Cache>> explains both.
* [[micronautAotResults]]*Micronaut AOT*: `runner-maot` − `shadow-maot` -381.3 ms (-394.6 to -373.6); `runner-stored`
− `shadow-maot` -348.6 ms (-354.1 to -321.0), so dropping Micronaut Launch's default Micronaut AOT for Runner still
starts sooner. With a JDK cache on both, Runner loses: `runner-maot-aot` − `shadow-maot-aot` +36.4 ms (+28.1 to
+43.2). See <<micronautAot,Micronaut AOT>>.
* *Size*: `runner-stored` is 2.44 times `shadow` on disk but 0.67 times gzipped, as images and downloads travel;
`runner-preserve` is 1.20 and 1.04 times.
* *Memory*: RSS counts a mapped archive's clean file-backed pages, so private memory is the like-for-like figure:
61.8 MiB less for `runner-stored` than `shadow`, 8.8 MiB less for the cached headline.
* *Entry stub vs reflection*: inconclusive; `runner-stored` − `runner-stored-reflection` spans zero at 20 pairs.
* *Mechanism*: see <<whyItIsFast,Why it is fast>>; no matched ablation isolates the index, so it is not a measured
cause.

== Running it yourself

[source,bash]
----
./gradlew :benchmarks:jmh
./gradlew :benchmarks:packagingComparison
./gradlew :benchmarks:startupBenchmark -Pbenchmarks.iterations=20
./gradlew :benchmarks:startupBenchmark -Pbenchmarks.iterations=20 -Pbenchmarks.optionalRows=true
./gradlew :benchmarks:startupBenchmark -Pbenchmarks.iterations=20 -Pbenchmarks.cpus=1 -Pbenchmarks.variants=shadow,runner-stored
----

CI runs them weekly and on demand, never as a pull request gate: shared runners are too noisy for that.
https://github.com/{githubSlug}/blob/master/benchmarks/README.md[`benchmarks/README.md`] has every property and the
harness details.
