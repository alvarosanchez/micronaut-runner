Each entry names a symptom, its cause and the fix. If your problem is not here, or a library misbehaves only in a
Runner JAR, please https://github.com/{githubSlug}/issues[report it].

== The build fails

Shadow and Runner write the same `-all.jar`:: The build fails before either archive is written, naming both tasks.
Remove the Shadow plugin, or give its JARs another classifier (<<quickStartGradle,Quick Start for Gradle>>).
`The dependency ... is a directory, and Micronaut Runner nests only JAR files`:: A dependency is a classes
directory. Package it as a JAR first; in a Maven reactor, run the build through the `package` phase.
`Unknown Micronaut Runner option '...'`:: A misspelled option, or one that a newer version of Runner added. The
message lists the options this version knows.
A Maven module that depends on the application fails to build:: A Runner JAR is not a library. Set
`micronaut.runner.classifier` in the application module, so that the Runner JAR is attached next to its main artifact
(<<configurationArchive,Main Class, Archive Name and Manifest>>).

== The build warns

The build log says that no Logback configuration was precompiled:: Only a notice: Logback reads `logback.xml` at
startup, as without precompilation. The reason says what kept it from being compiled
(<<precompiledLogback,Precompiled Logback Configuration>>).
`The startup profile looks stale; re-record it ...`:: The application changed since the profile was recorded. Record it
again and commit it (<<startupProfile,Startup Profile>>).
`No local-variable table was stripped, because ... reads local-variable tables at run time`:: You turned on
`stripLocalVariables`, but a library such as Paranamer, AspectJ or an old Spring needs the tables, so Runner keeps
them. To silence the warning, turn the option off again.

== The application behaves differently

The logging configuration in a mounted `application.yml`, `micronaut.config.files` or `--logger.config` is ignored::
Logback was precompiled, and the packaged `logback.xml` applies instead; `logger.levels.*` properties still apply. Set
the location with `-Dlogger.config` or `LOGGER_CONFIG`, or package with `precompileLogback=false`.
`-Dmicronaut.logback.precompiled=false` does not help here
(<<precompiledLogback,Precompiled Logback Configuration>>).
A `NullPointerException` says `"<local1>" is null`, or a debugger shows no local variables:: The archive was
packaged with `stripLocalVariables`, which drops dependency local-variable names
(<<localVariableTables,Dependency Local-Variable Names>>).
Stack traces have extra `pass:c[$$Lambda$R]` frames:: Lambdas were generated at build time
(<<desugaredLambdas,Lambdas Generated at Build Time>>).
The order of a dependency class's methods or JSON properties changed:: The archive was packaged with
`stripLocalVariables`, which rewrites dependency classes. Package without it.
A service provider added after packaging is not found:: If an agent or tool adds it to the class path, start with
`-Dmicronaut.runner.parent=system` (<<javaAgents,Java agents>>); otherwise, start with
`-Dmicronaut.runner.static-services=false` (<<staticServices,Precomputed Service Lookups>>).
`static-services.verify` reports a mismatch:: Start with `-Dmicronaut.runner.static-services=false`, package with
`staticServices=false`, and please report it.
An agent or tool cannot see the application's classes, or the application cannot see the agent's:: Start with
`-Dmicronaut.runner.parent=system` (<<javaAgents,Java agents>>).
A library finds no class through the system class loader, or a provider listed in `java.security` is missing::
In the single JAR, the system class loader does not see your dependencies
(<<compatibility,Compatibility and Limitations>>). Deploy an <<extract,extracted layout>>, or register the provider in
code with `Security.addProvider`.
A library finds no class or service only inside a parallel stream or a `CompletableFuture` task:: In the single JAR,
the threads of the common `ForkJoinPool` have the system class loader as their context class loader
(<<compatibility,Compatibility and Limitations>>). Pass an executor of your own, or deploy an
<<extract,extracted layout>>.
A library finds no dependencies through `java.class.path`:: A known limitation
(<<compatibility,Compatibility and Limitations>>). The library needs to use the context class loader instead.
`JCE cannot authenticate the provider ...`:: The JDK enforces JCE provider signing, as Oracle JDK and Oracle GraalVM
do. The provider's signature is verified only in an extracted layout of an archive packaged with `PRESERVE`: not in
the single JAR, and not in the extracted layout of a `STORED` or `HYBRID` archive. Package with `PRESERVE` and deploy
an <<extract,extracted layout>> (<<compatibility,Compatibility and Limitations>>).
`InaccessibleObjectException`, or warnings about `--add-opens`:: Add the packages to the `addOpens` or `addExports`
option (<<configurationOptions,Packaging Options>>).
`SecurityException: sealing violation`:: Two dependencies contribute classes to one sealed package. A shaded JAR hid
that conflict; exclude one of the duplicate dependencies.
A resource is not found, or the wrong one is found:: Resources resolve in class path order: your application first,
then the dependencies. List what the archive holds with `java -Dmicronaut.runner.mode=list -jar my-app-0.1-all.jar
META-INF/services`.
No beans are found:: List the merged metadata with `java -Dmicronaut.runner.mode=list -jar my-app-0.1-all.jar
META-INF/micronaut`. If it is empty, annotation processing did not run when the application was compiled.
A library fails to parse a resource URL:: A nested resource has a URL such as
`jar:file:/app/my-app-0.1-all.jar!/MICRONAUT-INF/lib/dep.jar!/name`, with two `!/`. Please report the library.

== The JDK AOT cache is not used

The application logs `[error][aot]` and starts slowly, or exits with 1 under `-XX:AOTMode=on`:: The cache does not fit
this start. `timestamp has changed` means a JAR's modification time changed; `incompatible CompressedOops::base()`
means the cache was created on JDK 27 or later without the <<aotCreationFlags,creation flags>>; other messages name a
different JDK build, garbage collector or heap size. Train again where the application runs, with the flags it uses
(<<jdkAotCacheRules,What a Cache Depends On>>).

== The application does not start, or starts slowly

The launcher exits with 2:: It printed the reason. `This runner jar was modified after it was packaged and must be
rebuilt` means the file was changed after packaging (<<archiveLifetime,Archive Lifetime>>);
`Unsupported runner jar format version` means the archive's index and its launcher come from different versions of
Runner, which a packaged archive never has. Rebuild it.
`Error: Invalid or corrupt jarfile`:: The JDK cannot read the file, which was truncated or appended to. Rebuild it.
Class loading fails in a running application:: The JAR was replaced under the running JVM. Restart it, and publish
new versions under new paths (<<archiveLifetime,Archive Lifetime>>).
The start is slower than expected:: Start with `-Dmicronaut.runner.timing=true`. Time spent after `application
entered` belongs to the framework and the application.
`-Dmicronaut.runner.timing=true` shows no `preload finished` line:: Preloading did not run: the archive carries no
startup profile, or the JVM sees only one CPU. Give the container at least 2 CPUs (<<startupProfile,Startup Profile>>).
RSS is higher than expected:: The mapped archive counts in RSS. Compare the memory the process does not share with the
OS page cache instead, or use `POSITIONAL` reads (<<archiveReads,Mapped or Positional Reads>>).

== Narrowing a problem down

To tell the build-time steps from the packaging itself, package once with `precompileLogback`, `desugarLambdas` and
`staticServices` set to `false`, and without `stripLocalVariables` if you turned it on. If the problem remains,
compare with `./gradlew run` or `mvn mn:run`, which use no Runner JAR.
